## 2. 分维度说明

### 2.1 需求维度（RK-01~02）
最大不确定来自 D-01~D-09 与 OI-05。处理铁律：**未决项不得由 Agent 自选数值**，一律按临时处置并标 `TBD(D-xx)`（宪章 §1）。续借本期明确不实现，避免范围蔓延（P-01 禁止）。

### 2.2 建模维度（RK-03~04）
读者类型与借出物类型"期限二维"均待确认。采用 STI + 类型字段 + 规则表，使建模与规则解耦，降低返工成本。

### 2.3 架构维度（RK-05~07）
分层与规则集中是本实验重点（P-05/P-06/P-08）。基线 `routes.py` 的反例（G-04/G-05/G-08）必须在实现中消解；事务边界锁定应用层。

### 2.4 数据库维度（RK-08~09）
STI 带来可空列与 SQLite 部分索引限制，`13` 已用应用层策略补强；规则快照是期限/罚款正确性的关键，必须落地版本关联。

### 2.5 权限维度（RK-10~12）
免真实认证是本期最大安全敞口，仅靠参数级角色校验。必须保证 `RoleGuard` 集中、不可绕过，且口令哈希存储。

### 2.6 Agent 使用维度（RK-13~15）
宪章核心是"Agent 起草、人类确认"。风险在于流程被跳过——需依赖 `19-ai-usage-log.md` 与审查状态字段兜底。
