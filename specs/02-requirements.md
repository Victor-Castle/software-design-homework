## 2. 总体描述

### 2.1 产品前景
"对话式图书管理系统"：用户用自然语言提需求，由 Agent 路由到后端 REST API（端口 8001，统一响应 `{code, message, data}`）执行业务。

### 2.2 用户特征与角色
| 角色 | 对应参与者 | 权限摘要（详见 BR-014 / P-07） |
|---|---|---|
| 读者 | A-01 / A-02 / A-03 | 注册、检索、本人借阅查询、预约、取消预约 |
| 图书管理员 | A-04 | 代理借书、代理还书、查询借阅信息（含代查） |
| 系统管理员 | A-05 | 办/删借阅证、增删管理员、增删标题/副本、维护规则 |

### 2.3 设计与实现约束
- 分层架构：表现层 / 应用服务层 / 领域层 / 基础设施层（P-05）。
- MVC：Controller 薄，业务规则不入 Controller（P-06）。
- 业务规则集中于 Policy / 领域服务（P-08）。
- 第一阶段不做真实登录认证，操作人由 `user_id` / `librarian_id` / `admin_id` 参数标识（F-01）。

### 2.4 假设与依赖
- 依赖 SQLite + FastAPI + SQLAlchemy 现有基线（`00` §9）。
- 假设规则数值可由系统管理员在后台维护（FR-016 与 D-02/D-03 解耦）。

## 5. 功能需求（Functional Requirements）

> 每条 FR 含：**描述 / 主参与者 / 前置条件 / 输入 / 处理 / 输出 / 验收标准（可验证）**。

### FR-001 注册读者账号
- **描述**：读者在线注册账号，填写用户名、口令、邮箱，并选择读者类型（本科/硕士/博士/专科/教师）。
- **主参与者**：A-01（系统代登记） / A-05（管理员代建）。
- **前置条件**：用户名未被占用。
- **输入**：`username`、`password`、`email`、`reader_type`。
- **处理**：创建用户记录；口令按 G-07 计划存储（第一阶段可沿用占位，详见 D-09 与 Q-22）；初始无有效借阅证（F-10）。
- **输出**：`{code:200, data:{user_id, reader_type}}` 或 `400`（用户名重复）。
- **验收标准**：
  1. 用唯一用户名注册返回 `code=200` 且生成 `user_id`。
  2. 重复用户名注册返回 `code=400` 且 `message` 明确。
  3. `reader_type` 在 {undergraduate, master, phd, junior, teacher} 集合内，否则 `400`。

### FR-002 办理借阅证
- **描述**：系统管理员为已注册读者开通借阅证，绑定读者类型与借阅权限，生成证号。
- **主参与者**：A-05。
- **前置条件**：目标用户存在且无有效借阅证（F-10，冲突则拒绝）。
- **输入**：`admin_id`、`user_id`（目标读者）。
- **处理**：生成证号 `CARD + 年份 + 6位序号`（F-09）；状态=有效；关联读者类型。
- **输出**：`{code:200, data:{card_no, user_id, reader_type}}` 或 `400`（已有有效证 / 用户不存在）。
- **验收标准**：
  1. 为无有效证用户办理，返回证号形如 `CARD2024xxxxxx`（6 位序号）。
  2. 同一用户重复办理返回 `400`，不生成第二个有效证。
  3. 用户不存在返回 `400`。

### FR-003 删除（注销）借阅证
- **描述**：系统管理员注销读者借阅证（软删除，保留历史）。
- **主参与者**：A-05。
- **前置条件**：目标借阅证有效，且该读者当前无在借 / 超期 / 预约记录（否则先清账）。
- **输入**：`admin_id`、`card_no` 或 `user_id`。
- **处理**：将借阅证置为失效（is_active=false），不物理删除。
- **输出**：`{code:200}` 或 `400`（存在未结清记录）。
- **验收标准**：
  1. 无在借/超期/预约的用户，注销成功、证状态=失效。
  2. 存在超期未还记录时返回 `400`，证保持有效。

### FR-004 添加图书管理员
- **描述**：系统管理员创建图书管理员账号。
- **主参与者**：A-05。
- **输入**：`admin_id`、`username`、`password`、`role=librarian`。
- **输出**：`{code:200, data:{user_id, role}}` 或 `400`。
- **验收标准**：
  1. 创建成功且 `role=librarian`，可被用于借还接口的身份校验（BR-013）。
  2. 重复用户名返回 `400`。

### FR-005 删除图书管理员
- **描述**：系统管理员停用/删除图书管理员账号。
- **主参与者**：A-05。
- **输入**：`admin_id`、`target_user_id`。
- **输出**：`{code:200}` 或 `400`（不能删除自己 / 不存在）。
- **验收标准**：
  1. 删除后该 `librarian_id` 不再通过借还接口的角色校验（返回 `400`）。
  2. 删除自身返回 `400`。

### FR-006 添加图书标题信息
- **描述**：系统管理员新增"题名/作品"层信息（标题）。
- **主参与者**：A-05。
- **输入**：`admin_id`、`title`、`author`、`isbn`、`publisher`、`category`、`published_year`、`description`。
- **处理**：创建 Title 记录；ISBN 唯一。
- **输出**：`{code:200, data:{title_id, isbn}}` 或 `400`（ISBN 重复）。
- **验收标准**：
  1. 合法标题创建成功并返回 `title_id`。
  2. 重复 ISBN 返回 `400`。

### FR-007 删除图书标题信息
- **描述**：系统管理员软删除标题（及其下无在借的副本）。
- **主参与者**：A-05。
- **前置条件**：该标题下所有副本均已删除或无可借副本且无在借记录（依赖 D-05 外的副本约束）。
- **输出**：`{code:200}` 或 `400`（存在在借副本）。
- **验收标准**：
  1. 无在借副本时删除成功（is_active=false）。
  2. 存在在借副本时返回 `400`，不删除。

### FR-008 添加馆藏副本
- **描述**：系统管理员为某标题新增实体副本（Item）。
- **主参与者**：A-05。
- **输入**：`admin_id`、`title_id`、`barcode`、`location`、`item_type`（借出物类型 IT-01~IT-05）。
- **处理**：创建 Item，状态=在馆；可选同步增加标题层 `total_copies`（Q-24 默认①）。
- **输出**：`{code:200, data:{item_id, barcode}}` 或 `400`（条码重复 / 标题不存在）。
- **验收标准**：
  1. 新增副本成功，状态=在馆，条码唯一。
  2. 条码重复返回 `400`。

### FR-009 删除馆藏副本
- **描述**：系统管理员删除（或报废）副本。
- **主参与者**：A-05。
- **前置条件**：该副本当前状态=在馆且未借出。
- **输出**：`{code:200}` 或 `400`（副本在借中）。
- **验收标准**：
  1. 在馆副本删除成功。
  2. 在借中的副本返回 `400`，不删除。

### FR-010 查询图书
- **描述**：按书名 / 作者 / 分类 / ISBN / 馆藏位置检索标题与副本信息。
- **主参与者**：A-01（检索可匿名，见 Q-03 默认）/ A-04 / A-05。
- **输入**：`keyword`、`author`、`category`、`location`、`page`、`page_size`。
- **输出**：`{code:200, data:{total, books[]}}`（字段含 `available_copies`、`status`）。
- **验收标准**：
  1. 按书名关键词返回匹配且 `is_active=true` 的标题列表。
  2. 多条件组合筛选结果正确（与单一条件结果交集一致）。
  3. 分页参数越界（`page<1` / `page_size>100`）返回 `400`。

### FR-011 借阅图书
- **描述**：图书管理员代理读者借阅某可借副本，生成借阅记录。
- **主参与者**：A-04（唯一执行者，F-02）；操作对象为读者 A-01。
- **前置条件**：
  1. 调用方为 `librarian`（BR-013）；目标读者存在且有有效借阅证。
  2. 读者在借数量 < 上限（BR-001）且无超期未还（BR-006）。
  3. 目标副本状态=在馆（BR-015 未缴罚款阻断策略 TBD）。
- **输入**：`librarian_id`、`user_id`、`item_id`（或 `title_id` + 自动选可用副本）。
- **处理**：扣减可借复本；创建借阅记录，`due_date = borrow_date + 期限`（BR-002/BR-003）；快照规则版本（BR-016）。
- **输出**：`{code:200, data:{record_id, due_date, remaining_quota}}` 或 `400`（超额 / 超期 / 无副本 / 非管理员）。
- **验收标准**：
  1. 管理员代理、条件满足时借书成功，`due_date` 符合读者类型期限（如教师=90 天后）。
  2. 数量已达上限返回 `400`，不生成记录。
  3. 存在超期未还记录返回 `400`（BR-006）。
  4. **读者（`user_id`）直接调用返回 `400`，借书仅可由 librarian 完成（F-02）**。
  5. 无可借副本返回 `400`。

### FR-012 归还图书
- **描述**：图书管理员代理读者归还副本，并触发超期罚款计算。
- **主参与者**：A-04（唯一执行者，F-02）。
- **输入**：`librarian_id`、`record_id`。
- **处理**：记录 `return_date`、状态=已归还；复本+1；若 `return_date>due_date` 调用 FR-015 计算罚款（BR-007）。
- **输出**：`{code:200, data:{book_title, days_overdue, fine}}` 或 `400`（记录不存在/已归还）。
- **验收标准**：
  1. 正常归还成功，复本+1，状态=已归还。
  2. 已超期的归还，返回正确的 `fine`（按 BR-004 费率 × 天数）。
  3. 非管理员调用返回 `400`。

### FR-013 查询借阅信息
- **描述**：查询个人（读者本人）或代查（管理员）的借阅记录。
- **主参与者**：A-01（本人）/ A-04（代查任意读者）/ A-05。
- **输入**：查询主体（本人 `user_id` 或管理员 `target_user_id`）、`status` 过滤（borrowing/returned/overdue/reserved）。
- **输出**：`{code:200, data:{records[], total}}`。
- **验收标准**：
  1. 读者查询本人记录成功且只含本人数据。
  2. 管理员可查询任意读者记录（Q-07 默认包含）。
  3. 读者尝试查询他人 `user_id` 返回 `400`（越权，BR-014）。

### FR-014 预约图书
- **描述**：读者对无可用副本的标题发起预约，进入 FIFO 队列。
- **主参与者**：A-01。
- **前置条件**：该标题当前无可用副本；同一读者对同一标题无有效预约（BR-009）。
- **输入**：`user_id`、`title_id`。
- **处理**：创建预约，时间 `createdAt`；按 BR-008 入队；状态=pending。
- **输出**：`{code:200, data:{reservation_id, queue_position}}` 或 `400`（有可用副本 / 重复预约）。
- **验收标准**：
  1. 无可用副本时预约成功，且队列位置按 `createdAt` 升序（BR-008）。
  2. 同一读者重复预约同一标题返回 `400`（BR-009）。
  3. 标题仍有可用副本时返回 `400`（提示直接借阅）。

### FR-015 计算超期罚款
- **描述**：依据借出物类型规则计算超期罚款金额（归还时触发 / 定时标记）。
- **主参与者**：系统（触发），由 FR-012 调用。
- **输入**：`item_type`、`due_date`、`return_date`。
- **处理**：超期天数按 BR-005 口径；金额 = 天数 × 费率（BR-004）；封顶策略 TBD(D-03)。
- **输出**：`fine`（元，保留 2 位小数）或 0（未超期）。
- **验收标准**：
  1. 超期 N 天的中文图书罚款 = N × 0.1 元（例：超 10 天 = 1.0 元）。
  2. 超期 N 天的外文图书罚款 = N × 0.2 元。
  3. 论文超期 N 天 = N × 0.5 元。
  4. 未超期返回 0。

### FR-016 维护借阅规则和罚款规则
- **描述**：系统管理员维护借阅上限、借阅期限、罚款费率等规则参数（集中化，`04-business-rules.md` 的 Policy 载体）。
- **主参与者**：A-05。
- **输入**：`admin_id`、规则键值（如 `borrow_limit.teacher`、`loan_period.master`、`fine_rate.chinese_book`）。
- **处理**：更新规则表；新规则对**未来**借阅生效（历史快照不变，BR-016）。
- **输出**：`{code:200, data:{rule_key, value}}` 或 `400`（非法取值）。
- **验收标准**：
  1. 修改后新增借书的期限/罚款按新值（或旧快照）正确应用，互不影响。
  2. 非法取值（负数、未知 key）返回 `400`。
  3. 规则变更在 `10-change-requests.md` 可追溯（P-04）。

### FR-017 取消预约（扩充）
- **描述**：读者取消本人对某标题的有效预约。
- **主参与者**：A-01。
- **输入**：`user_id`、`reservation_id`。
- **输出**：`{code:200}` 或 `400`（非本人 / 非 pending）。
- **验收标准**：
  1. 取消本人 pending 预约成功，释放队列位置，后续预约前移。
  2. 取消他人预约返回 `400`。

### FR-018 查询与记录罚款（不接支付，扩充）
- **描述**：查询读者的罚款明细与缴纳状态（仅记录，不对接支付网关，OOS-01）。
- **主参与者**：A-01（本人）/ A-04（代查）。
- **输入**：`user_id` / `target_user_id`。
- **输出**：`{code:200, data:{fines[], total_unpaid}}`。
- **验收标准**：
  1. 返回该读者所有罚款记录及状态（unpaid/paid/waived）。
  2. 不触发任何真实扣款动作（OOS-01 合规）。

### FR-019 操作人身份与权限校验（跨切面，扩充）
- **描述**：所有穿越 API 边界的写操作必须校验操作人角色（F-01 简化认证下的替代保障，P-07）。
- **主参与者**：系统（守卫）。
- **处理**：借还接口校验 `librarian_id` 角色；后台接口校验 `admin_id` 角色；读者接口校验 `user_id` 角色=reader。
- **输出**：不通过则返回 `code=400` 且 `message` 指明权限不足。
- **验收标准**：
  1. 以非 librarian 身份调用 FR-011/FR-012 被拒。
  2. 以非 admin 身份调用 FR-002~FR-009/FR-016 被拒。
  3. 读者查询他人记录（FR-013）被拒。

### 7.1 读者类型借阅规则

**BR-001 借阅数量上限**（来源 F-04 / Q-11）

- 采用**总量上限**；按借出物类型的子上限暂不设置（Q-11）。

| 读者类型 | 期限（天） |

- 借书时按读者类型确定 `due_date`（BR-003 叠加借出物类型维度）。

**BR-003 借阅期限二维取值**：期限为"读者类型 × 借出物类型"二维规则；读者类型维度已定（BR-002），**借出物类型维度期限 TBD(D-02)**，缺省取读者类型值（Q-08 默认）。

### 7.2 借出物类型与罚款规则

**BR-004 罚款费率**（来源 F-06 / Q-14，单位：元/天）

| 借出物类型 | 费率 |

**BR-005 超期天数口径**：按自然日、不足一天向上取整为一天（Q-15 默认①）；是否排除节假日 TBD(D-03)。

**BR-008 预约排队规则**：允许多人排队，按 `createdAt` 升序 FIFO（F-08）。

**BR-009 预约去重规则**：同一读者对同一标题不能有多个有效（pending）预约（F-08/Q-32）。

**BR-010 预约保留期与取消**：保留期与到馆通知 TBD(D-05)；允许读者主动取消（FR-017）。有效预约状态集合：`{pending, fulfilled, cancelled, expired}`。
