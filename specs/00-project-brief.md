## 1. 项目背景

本项目是《软件设计与体系结构》课程的配套实验项目，用于系统训练以下能力：

1. **需求分析**：从业务描述中识别参与者、用例、业务规则与非功能需求；
2. **UML 建模**：用例图、类图、顺序图、状态图、活动图、包图/组件图、部署图；
3. **架构设计**：分层架构（Presentation / Application / Domain / Persistence）与 MVC 模式；
4. **数据库设计**：概念模型（E-R）→ 逻辑模型 → 物理表结构；
5. **详细设计**：类职责、方法签名、业务规则与状态流转；
6. **代码实现**：可运行的后端服务 + 自动化测试。

工程已提供一份**基础代码骨架**（`backend/`），作为实验起点；实验要求在其之上完成分析、设计与扩展实现。

## 2. 项目目标

开发一个**图书管理系统**，支持：

- 读者注册
- 借阅证管理
- 图书借阅
- 图书归还
- 借阅查询
- 图书预约
- 系统维护
- 超期罚款

系统需覆盖从"读者类型差异"到"借出物类型差异"两类核心业务规则维度，并对外提供可调用、可测试的 API 能力。

### 2.1 非功能目标（约束性目标）

| 编号 | 类别 | 目标 |
|---|---|---|
| NFR-01 | 可维护性 | 采用分层架构，层间依赖单向向下，禁止跨层反向调用 |
| NFR-02 | 可测试性 | 核心业务规则（借阅配额、超期、罚款、预约）必须有自动化单元测试覆盖 |
| NFR-03 | 可追溯性 | 用例 → 领域类 → 接口 → 测试用例之间保持编号可追溯 |
| NFR-04 | 一致性 | 穿过 API 边界的字段名（`user_id`、`book_id`、`record_id`、`code`、`due_date`、`total` 等）必须与后端实现严格一致 |
| NFR-05 | 可运行性 | 工程必须可一键启动（本地 SQLite，无需外部中间件），并提供接口自验证方式 |
| NFR-06 | 安全性（基础） | 不得明文存储口令（基线为占位实现，实验实现阶段须升级为哈希存储）；管理员操作需鉴权 |

## 3. 目标用户（参与者 Actor）

| 编号 | 参与者 | 说明 |
|---|---|---|
| A-01 | 读者（Reader） | 系统的核心使用者，注册账号、持借阅证借还图书。`Reader` 是抽象基类 |
| A-02 | 学生读者（StudentReader） | `Reader` 的子类，含本科生 / 研究生 / 博士生 / 专科生 |
| A-03 | 教师读者（TeacherReader） | `Reader` 的子类，借阅数量与期限优于学生读者 |
| A-04 | 图书管理员（Librarian） | 办理借阅证、办理借还手续、维护图书标题信息、维护馆藏副本 |
| A-05 | 系统管理员（SystemAdmin） | 维护管理员账号、维护系统参数（借阅规则、罚款规则）、系统运维 |

> **建模提示**：A-02/A-03 与 A-01 构成**泛化关系**；A-04/A-05 属于**系统内部角色**，在用例图中置于"系统边界"内侧或作为独立参与者。

## 4. 主要业务（用例清单）

| 编号 | 用例 | 主参与者 | 说明 |
|---|---|---|---|
| UC-01 | 注册账号 | A-01 读者 | 读者在线注册账号，填写基本信息，选择读者类型 |
| UC-02 | 办理借阅证 | A-04 图书管理员 | 管理员为已注册读者审核并开通借阅证，绑定读者类型与借阅权限 |
| UC-03 | 借阅图书 | A-01 读者 / A-04 图书管理员 | 校验借阅证有效性、借阅配额、在借可借副本，生成借阅记录并扣减可借复本 |
| UC-04 | 归还图书 | A-01 读者 / A-04 图书管理员 | 归还副本，判定是否超期，按借出物类型计算罚款 |
| UC-05 | 查询借阅信息 | A-01 读者 / A-04 图书管理员 | 查询个人在借、历史、超期、预约记录 |
| UC-06 | 预约图书 | A-01 读者 | 当可借复本为 0 时预约，副本到馆后通知取书 |
| UC-07 | 维护图书标题信息 | A-04 图书管理员 | 对"题名/作品"层（Title）的增删改查：书名、作者、ISBN、出版社、分类 |
| UC-08 | 维护馆藏副本 | A-04 图书管理员 | 对"实体副本"层（Item/Copy）的增删改查：条码、馆藏位置、状态 |
| UC-09 | 维护管理员 | A-05 系统管理员 | 管理员账号的创建、禁用、权限分配 |
| UC-10 | 计算超期罚款 | 系统（定时/归还时触发） | 依据借出物类型的超期规则与罚款规则计算金额，写入罚款记录 |

### 4.1 用例关系说明

- `UC-03 借阅图书` **<<include>>** 校验借阅配额（前置条件检查）；
- `UC-03 借阅图书` **<<extend>>** `UC-06 预约图书`（当无可借副本时转向预约）；
- `UC-04 归还图书` **<<include>>** `UC-10 计算超期罚款`（仅当超期时执行）；
- `UC-02 办理借阅证` **<<include>>** `UC-01 注册账号`（先有账号后有证）；
- `UC-07` 与 `UC-08` 是**两级维护**：先有"标题（作品）"，再挂接若干"副本（馆藏）"。

## 5. 读者类型（Reader Type）

不同读者类型具有**不同的借阅数量上限**与**借阅期限**。下表为**初始默认规则**，具体数值在详细设计阶段以"规则表"形式配置化（可维护，非硬编码）。

| 编号 | 读者类型 | 父类 | 最大借阅数量 | 借阅期限 | 续借 |
|---|---|---|---|---|---|
| RT-01 | 本科生（Undergraduate） | StudentReader | 待定（建议 5） | 待定（建议 30 天） | 待定 |
| RT-02 | 研究生（Master） | StudentReader | 待定（建议 8） | 待定（建议 60 天） | 待定 |
| RT-03 | 博士生（PhD） | StudentReader | 待定（建议 10） | 待定（建议 90 天） | 待定 |
| RT-04 | 专科生（JuniorCollege） | StudentReader | 待定（建议 4） | 待定（建议 30 天） | 待定 |
| RT-05 | 教师（Teacher） | TeacherReader | 待定（建议 15） | 待定（建议 90 天） | 待定 |

> **设计约定**：读者类型采用**策略/规则表**方式实现（而非在代码里大量 `if-else`），便于后续按类型扩展。

## 6. 借出物类型（Loanable Item Type）

不同借出物类型具有**不同的超期规则**与**罚款规则**。

| 编号 | 借出物类型 | 是否可外借 | 超期规则 | 罚款规则 |
|---|---|---|---|---|
| IT-01 | 中文图书（ChineseBook） | 是 | 按天计超期 | 按天计费（建议 0.5 元/天） |
| IT-02 | 外文图书（ForeignBook） | 是 | 按天计超期，期限通常更长 | 按天计费，费率高于中文图书 |
| IT-03 | 中文杂志（ChineseMagazine） | 是 | 短期借阅，按天计超期 | 按天计费，费率较低 |
| IT-04 | 外文杂志（ForeignMagazine） | 是 | 短期借阅，按天计超期 | 按天计费 |
| IT-05 | 论文（Thesis） | 受限（通常馆内阅览） | 受限外借，超期从重 | 罚款费率最高 |

> **建模提示**：借出物（LoanableItem）与"标题（Title）"分离——一个标题可对应多个副本（Item），借阅作用在**副本**上，规则作用在**类型**上。

### 6.1 罚款规则要素

罚款计算至少需考虑：

1. 超期天数（自然日 / 工作日，需明确）；
2. 借出物类型对应的费率（元/天）；
3. 是否有罚款上限（封顶金额）；
4. 是否存在免罚期（grace period）；
5. 罚款缴纳状态（未缴 / 已缴 / 已减免）与是否冻结借阅权限。

## 8. 范围边界（Scope）

### 8.1 本期实现（In Scope）

- 读者注册与登录；
- 借阅证（与读者类型绑定的借阅权限）管理；
- 图书检索（按书名 / 作者 / 分类 / ISBN）；
- 借阅、归还、续借类流通业务；
- 借阅记录与个人借阅信息查询；
- 图书预约；
- 图书标题信息与馆藏副本维护；
- 管理员维护；
- 超期判定与罚款计算。

### 8.2 暂不实现（Out of Scope）

| 编号 | 排除项 | 说明 |
|---|---|---|
| OOS-01 | 支付系统真实扣款 | 仅记录罚款金额与缴纳状态，不对接支付网关 |
| OOS-02 | 图书条码扫描硬件 | 不涉及硬件驱动与设备集成 |
| OOS-03 | 复杂全文检索 | 仅支持结构化字段匹配/模糊查询，不引入搜索引擎 |
| OOS-04 | 多校区馆藏调拨 | 不涉及跨馆/跨校区的调拨与物流 |
| OOS-05 | 微信 / 统一身份认证登录 | 仅实现本地账号口令登录 |

## 9. 现有基线工程（Baseline Code）

> 本节描述**老师提供的基础工程现状**，是后续设计与实现的起点。**实验一阶段只读，不修改。**

| 项 | 现状 |
|---|---|
| 目录 | `backend/`（`main.py`、`app/models.py`、`app/routes.py`） |
| 语言 / 框架 | Python + FastAPI |
| ORM / 数据库 | SQLAlchemy + SQLite（`backend/app/library.db`） |
| 启动方式 | `cd backend && python main.py` |
| 服务端口 | `8001`（避开 8000） |
| 接口风格 | REST，统一返回 `{code, message, data}`（`200` 成功 / `400` 业务错误 / `500` 系统错误） |
| 已有数据模型 | `User`、`Book`、`BorrowRecord` |
| 已有接口 | 登录、查询用户、图书检索、图书详情、图书列表、借阅配额检查、借阅、归还、借阅记录查询、预约、健康检查 |

### 9.1 基线已知差距（Gap，供后续实验补齐）

| 编号 | 差距 | 目标状态 |
|---|---|---|
| G-01 | 无"读者类型"维度（`User.max_borrow` 为平铺字段） | 引入 `Reader` 继承体系 + 借阅规则表 |
| G-02 | 无"借出物类型"维度（仅单一 `Book`） | 引入 `LoanableItem` 类型体系与差异化罚款规则 |
| G-03 | 无"标题 / 副本"两级模型 | 拆分为 `Title` 与 `Item`（馆藏副本） |
| G-04 | 借阅期限硬编码 30 天 | 由读者类型 × 借出物类型共同决定 |
| G-05 | 罚款规则硬编码 0.5 元/天，且无罚款实体 | 抽取罚款规则，新增罚款记录实体 |
| G-06 | 无预约实体（预约复用借阅记录，状态 `reserved`） | 独立预约模型，支持排队与到馆通知 |
| G-07 | 口令明文存储 | 哈希 + 盐存储 |
| G-08 | 无分层 Service / Repository（逻辑集中在路由层） | 按分层架构重构 |
| G-09 | 无自动化测试 | 补充单元测试与接口测试 |

## 11. 术语表（初稿，详见 `01-glossary.md`）

| 术语 | 英文 | 定义 |
|---|---|---|
| 读者 | Reader | 持有借阅证、可借阅图书的系统用户，按类型区分借阅权限 |
| 借阅证 | LibraryCard | 读者的借阅凭证，记录证号、状态、有效期与读者类型 |
| 标题 | Title | 作品的题名层信息（书名、作者、ISBN、出版社、分类） |
| 馆藏副本 | Item / Copy | 某一标题下的具体物理副本，具有唯一条码与馆藏位置 |
| 借出物 | LoanableItem | 可被借出的资源抽象，含中文/外文图书、中文/外文杂志、论文 |
| 借阅记录 | Loan / BorrowRecord | 一次借阅行为的记录，含借出日、应还日、实还日、状态 |
| 预约 | Reservation | 在无可借副本时对标题发起的预约请求 |
| 罚款 | Fine | 因超期归还产生的费用记录 |
| 超期 | Overdue | 实际归还时间晚于应还日期 |
